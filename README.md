# Rosepsy — سامانه مشاوره روان‌شناختی سازمانی

پیاده‌سازی سند تحلیل نیازمندی‌ها (نسخه ۲.۰ — فرم مبنا RS-PS-04-01).
نسخه اولیه یک‌سازمانی: PostgreSQL + FastAPI + React/Vite + Docker Compose + Nginx.

## پیش‌نیازها

- Docker Desktop (شامل Docker Compose v2) — حتماً اجرا باشد
- Git

## راه‌اندازی عملیاتی

1) تنظیمات محیط (اسکریپت‌ها این کار را خودکار انجام می‌دهند؛ برای دستی):

    Copy-Item .env.example .env
    # مقادیر POSTGRES_PASSWORD و AUTH_SECRET_KEY را تصادفی کنید (در DATABASE_URL هم)

2) ساخت و اجرا:

    docker compose build
    docker compose up -d db
    docker compose run --rm migrate
    docker compose up -d

3) ایجاد مدیر اولیه (فرمان امن — بند ۴.۲ سند):

    docker compose run --rm api python create_admin.py

    نام کاربری و رمز تصادفی فقط یک بار چاپ می‌شود؛ آن را در جای امن ذخیره کنید.
    در اولین ورود، تغییر رمز الزامی است (must_change_password).

4) دسترسی:

    - وب:          http://localhost:8080
    - مستندات API:  http://localhost:8080/api/v1/docs

نکته: مقدار ENVIRONMENT=development فقط برای تست محلی روی HTTP است.
پیش از ورود داده واقعی: HTTPS فعال شود و ENVIRONMENT=production قرار گیرد
(Cookie مربوط به Refresh Token در production فقط Secure ارسال می‌شود).

## توسعه

    docker compose -f compose.dev.yml up -d --build db api
    docker compose -f compose.dev.yml run --rm api alembic upgrade head
    cd frontend
    npm install
    npm run dev

    وب توسعه: http://localhost:5173  (پروکسی /api به http://localhost:8000)

## پشتیبان‌گیری

    docker compose --profile ops run --rm backup

خروجی در پوشه backups/ ذخیره می‌شود.
طبق بند ۱۳.۱ سند، پشتیبان باید به مقصد جداگانه از سرور اصلی نیز منتقل شود.

## بازیابی (نمونه)

    docker cp backups\rosepsy_db_<TIMESTAMP>.dump rosepsy-db-1:/tmp/b.dump
    docker compose exec db pg_restore -U rosepsy -d rosepsy --clean --if-exists /tmp/b.dump

## فاز ۲۷ — ClamAV واقعی، خروجی ایمیل اعلان‌ها و گزارش انطباق DPO (v0.27.0)
- **B39-plus آنتی‌ویروس واقعی:** سرویس اسکن سه‌بستری — clamd از راه TCP با پروتکل INSTREAM (حالت استاندارد docker compose) → clamscan بومی (subprocess) → قواعد پایه داخلی شامل امضای استاندارد EICAR؛ سیاست fail-closed برای پاسخ ERROR و fail-soft برای قطعی clamd (توقف آپلود ممنوع). سرویس clamav/clamav:1.4.6 در compose با StreamMaxLength=100M و volume مستقل پایگاه امضا (تگ 1.4.2 ساده هرگز در Docker Hub منتشر نشده بود)
- **حذف متادیتای تصاویر:** EXIF/GPS/ICC تصاویر JPEG/PNG/WEBP پیش از ذخیره حذف می‌شود (Pillow)؛ جهت EXIF داخل پیکسل «پخته» می‌شود و تصاویر متحرک دست‌نخورده می‌مانند؛ ثبت «فراداده حذف شد» در جزئیات اسکن
- endpoint وضعیت اسکنر: GET /files/scan-status (شفافیت عملیاتی) و rescan با اسکنر فعال؛ نام اسکنر در file_scans ثبت می‌شود (clamav-clamd / clamav-clamscan / builtin-rules)
- **B12+ خروجی ایمیل اعلان‌ها:** جدول `email_outbox` (صف ADR-02) — هر اعلان برای گیرنده دارای ایمیل در صف می‌رود؛ ارسال SMTP با STARTTLS/SMTPS، سقف تلاش ۵ و ثبت خطا؛ بدون SMTP ردیف‌ها «disabled» می‌شوند (شفافیت، بدون نشت سیاه‌چاله)؛ سیاست «عدم افشای محتوای بالینی» در ایمیل برقرار است
- API صف: GET/POST /email-outbox (+/process) برای مدیر سازمان/سامانه با audit؛ اتصال شفاف به notify_user (شکست ایمیل جریان اصلی را متوقف نمی‌کند)
- **B41+ گزارش DPO:** نقش جدید «حسابرس حفاظت داده (DPO)» + GET /reports/dpo — انطباق رضایت (per-kind فعال/ابطال، نسخه‌ها، رکوردهای بدون نسخه)، دسترسی (رخدادهای حساس، ورود ناموفق، بازیگران متمایز)، امنیت فایل (وضعیت اسکن، اسکنرهای استفاده‌شده، وضعیت بسترها)، کانال ایمیل و حساب‌ها/نشست‌ها؛ کاملاً تجمیعی و بی‌نام (بند ۱۵) با audit اجرای گزارش
- صفحه `/dpo-report` در فرانت برای مدیر سازمان/سامانه/DPO با کارت‌های KPI و جداول وضعیت
