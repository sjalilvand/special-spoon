۲) به‌روزرسانی سامانه (ارتقا)

دستور اصلی و همیشگی (در PowerShell با دسترسی Administrator):

powershell -ExecutionPolicy Bypass -File C:\rosepsy\app\deploy\rosepsy-server-native.ps1 -Mode upgrade

این دستور به‌ترتیب: کد را از گیت می‌کشد ← وابستگی‌های pip/npm را نصب می‌کند ← فرانت‌اند و پنل را build می‌کند ← مایگریشن بانک را اعمال می‌کند ← seedها را به‌روز می‌کند ← Caddyfile را با قالب فعلی هم‌راستا و validate می‌کند ← سرویس‌ها را ری‌استارت می‌کند ← بررسی سلامت نهایی می‌کند.

اگر پیام «اسکریپت استقرار در همین اجرا به‌روزرسانی شد» را دیدید، کد اپ در همان اجرا اعمال می‌شود اما بهبودهای وب‌سرور (پورت 8080، قوانین فایروال، تشخیص‌های جدید) پس از پایان اجرا، با یک اجرای دوبارهٔ همان دستور فعال می‌شوند.

حالت‌های دیگر اسکریپت:

حالتکاربرد
-Mode upgradeارتقای عادی (همیشه همین)
-Mode statusنمایش وضعیت سرویس‌ها و پورت‌ها بدون تغییر
-Mode doctorتشخیص مشکلات محیط
-Mode setupنصب از صفر (روی سرور جاری دیگر اجرا نکنید)

۳) سلامت‌سنجی روزانه

وضعیت سرویس‌ها

Get-Service rosepsy-*

هر پنج سرویس باید Running باشد.

تست سریع وب و API (داخل سرور)

curl.exe -s -o NUL -w "panel: %{time_total}s`n" http://127.0.0.1/panel/
curl.exe -s -o NUL -w "api:   %{time_total}s`n" http://127.0.0.1:8000/api/v1/health

مقادیر سالم: هر دو زیر ۱ ثانیه (نمونهٔ سرور جاری: ۰٫۰۰۴ و ۰٫۰۱۵ ثانیه).

تست از بیرون (موبایل با اینترنت اپراتور): آدرس http://130.185.73.157/ و در صورت باز نبودن 80 از سمت اپراتور، آدرس جایگزین http://130.185.73.157:8080/. توجه کنید مرورگرها اگر آدرس را بدون http تایپ کنید ابتدا https را امتحان می‌کنند و چون 443 بسته است «در حال انتظار» به‌نظر می‌رسد.

بعد از باز شدن 443 و تنظیم DNS، گواهی HTTPS را بگیرید:

cd C:\rosepsy\app\deploy\windows
powershell -ExecutionPolicy Bypass -File .\rosepsy-server-tls.ps1
اجرای اسکریپت ps1 از داخل پوشهٔ خودش باید با پیشوند .\ باشد (.\rosepsy-server-tls.ps1)؛ در غیر این صورت PowerShell با CommandNotFoundException مواجه می‌شود چون پوشهٔ جاری در مسیر جست‌وجوی فرمان‌ها نیست.

۶) لاگ‌ها و ردیابی خطا

  • لاگ هر سرویس: C:\rosepsy\logs\rosepsy-api\ ، ...\rosepsy-caddy\ و غیره
  • ترنسکریپت نصب/ارتقای اسکریپت: C:\rosepsy\logs\native-setup-*.log
  • خطای 500 با پیام «نامشخص» در پنل = معمولاً ناهمگامی اسکیما؛ اسکریپت ارتقا به‌صورت خودکار وارسی و ترمیم فاز ۷۰ را اجرا می‌کند و در API خطا به 503 با پیام راهنما ترجمه می‌شود.

۷) پشتیبان‌گیری و بازیابی

خودکار: وظیفهٔ زمان‌بندی‌شدهٔ Rosepsy Backup هر روز ساعت ۰۲:۳۰ اجرا می‌شود (اسکریپت: C:\rosepsy\scripts\pg-backup.ps1) و با pg_dump -Fc در C:\rosepsy\backups\rosepsy-YYYYMMDD-HHmm.dump ذخیره می‌کند؛ نسخه‌های قدیمی‌تر از ۱۴ روز خودکار حذف می‌شوند.

دستی:

C:\rosepsy\runtime\pgsql\bin\pg_dump.exe -U rosepsy -h 127.0.0.1 -p 5432 -Fc -f C:\rosepsy\backups\manual.dump rosepsy

بازیابی (هنگام نیاز — دقت کنید بانک فعلی جایگزین می‌شود):

C:\rosepsy\runtime\pgsql\bin\pg_restore.exe -U rosepsy -h 127.0.0.1 -p 5432 -d rosepsy --clean C:\rosepsy\backups\rosepsy-YYYYMMDD-HHmm.dump
رمز PostgreSQL از متغیر POSTGRES_PASSWORD در فایل .env خوانده می‌شود. پیش از بازیابی، سرویس API را موقتاً متوقف کنید: Stop-Service rosepsy-api و پس از آن دوباره اجرا کنید.

۸) خطاهای رایج و راه‌حل

عارضهعلتراه‌حل

«اسکریپت در همین اجرا به‌روزرسانی شد»خود اسکریپت در همان اجرا از گیت به‌روز شدهپس از پایان اجرا، همان دستور ارتقا را یک بار دیگر بزنید
موبایل سایت را باز نمی‌کند / به‌نظر کند استمرورگر موبایل پیش‌فرض https را امتحان می‌کند و 443 در فایروال هاستینگ بسته استبا http:// صریح یا پورت :8080 تست کنید؛ راه‌حل قطعی باز شدن 443 است (بخش ۴)
خطای «duplicate key» هنگام seed مشاورانحساب هم‌نام قبلیاصلاح‌شده (seedها idempotent) — اجرای مجدد ارتقا کافی است
هشدارهای زرد Caddyfile در لاگ ارتقاheader_up X-Forwarded-For زائد و قالب‌بندی فایلبی‌اثر — رفتار پیش‌فرض Caddy همان هدر را می‌فرستد؛ نیازی به اقدام نیست

۹) پرداخت آنلاین — وضعیت و کلیدها

  • وضعیت فعلی: درگاه شبیه‌ساز داخلی (sandbox) تا وقتی merchant_id خالی است — رزرو آنلاین کار می‌کند و پول واقعی جابه‌جا نمی‌شود.
  • کلیدهای .env: PAYMENT_GATEWAY ، ZARINPAL_MERCHANT_ID ، ZARINPAL_SANDBOX ، PUBLIC_BASE_URL
  • پس از دریافت merchant_id از زرین‌پال: مقادیر را در C:\rosepsy\app\.env تنظیم و ZARINPAL_SANDBOX=false و سپس Restart-Service rosepsy-api.
  • راهنمای کامل درخواست درگاه: فایل docs/zarinpal-gateway-request.html روی سایت (بخش پیوست همین سند).
  • تأیید پرداخت همیشه سمت سرور انجام می‌شود؛ callback تکراری بی‌اثر است (idempotent).

۱۰) دستورات اضطراری

Restart-Service rosepsy-api
Restart-Service rosepsy-caddy
Restart-Service rosepsy-pg

ری‌استارت تک‌تک سرویس‌ها (با دسترسی Administrator).

C:\rosepsy\runtime\caddy\caddy.exe validate --config C:\rosepsy\etc\Caddyfile --adapter caddyfile

اعتبارسنجی پیکربندی Caddy؛ برای بازگردانی، جدیدترین Caddyfile.bak-* را کپی و سرویس را ری‌استارت کنید.

Push-Location C:\rosepsy\app\backend
& "C:\rosepsy\runtime\venv\Scripts\python.exe" create_admin.py
Pop-Location

ساخت ادمین جدید.

Stop-Service rosepsy-api
# نگهداری/بازیابی بانک
Start-Service rosepsy-api

توقف/اجرای موقت API برای عملیات بانک.
